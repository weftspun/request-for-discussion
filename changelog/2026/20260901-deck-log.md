# V-Sekai Multiplayer Fabric Deck Log — 2026-09-01 (Tuesday)

Date: 2026-09-01

The weftspun-fdb cluster, the openbao instance on top of it, the spot broker, and the chibifire.com app were gone
from Fly at start of day. Tigris `weftspun-fdb-blob` and R2 `weftspun-fdb-dr` had both survived, so the day was

The runbook had called itself theatre as of 2026-08-31 because RFD 2141's break-glass CA was not in 1Password;
this run landed that CA at DR-time and the theatre note is retired.

The R2 snapshot described restorable, 0.19 days old, 99 644 bytes — RFD 2143's 2026-08-31 measurement had put
the cluster at `Sum of key-value sizes = 0 MB`, so 100 KB agrees: this is Bao's PKI mount metadata and internal
system tables. The `fdbrestore -w` from R2 into the fresh single-node TLS cluster is running as this entry is
written.

  which records the first run of RFD 2143's DR runbook against a real disaster and lands the break-glass
  CA RFD 2141 named as its own prerequisite. `op://Personal/FDB-CA/{cert,key}` now holds a P-384 self-signed
  root and its private key, from which the recovered cluster's machine leaves are minted; RFD 2141's phases
  2–3 will rotate them to certificates signed by the CA Bao's PKI mount holds, once Bao is unsealed against
  the restored FDB.
- `logbook-rfd2144-dr-runbook-first-run.md`, which captures the five inline defects the runbook did not
  name — no home for `WEFT_FDB_CLUSTER_ID`, Bao secrets in `notesPlain`, Fly `storage create` refusing an
  existing bucket, health checks fail-closed on first deploy, and `zsh` `read -p` silent in the AI session's
  `!` context — plus the T+ timeline as it is measured.
- `weftspun-fdb cluster id` in 1Password, holding the freshly minted `WEFT_FDB_CLUSTER_ID`. The runbook now
  reads this rather than assuming any prior copy exists.

## Changed

- `weftspun-fdb` is a new Fly app with new coordinator addresses and a new cluster ID. Clients' cluster files
  change to `weft:<newid>@<newcoords>`. Coordinator addresses change on any rebuild anyway, so the identity
  change costs nothing extra to consume.
- The cluster runs at `WEFT_FDB_MACHINES=1` and `WEFT_FDB_REDUNDANCY=single` while the restore runs and Bao
  comes back up. RFD 2143 wants three at `double` before real writes; that scale-up is scheduled after Bao
  unseals and the machine leaves are rotated to the restored CA.
- The R2 S3 access key `weftspun-fdb-dr s3` in 1P was used to bootstrap the restore. It rotates and revokes at
  end of DR, per RFD 2143 step 8, with the replacement key going into Bao once Bao is back.

## Fixed

- RFD 2143's "the runbook is theatre" line, which had held since 2026-08-31. RFD 2141's prerequisite — the
  break-glass CA in 1P — landed in passing during this DR, and the runbook then ran end-to-end.
- `fdb-entrypoint.sh` in `6-datasource/store/fly/` gated the `[backup_agent]` config block on Tigris
  credentials being set. An R2-only setup — precisely the DR path — spawned no backup agent, so
  `fdbrestore` queued forever. Now gates on `$backup = 1 || $backup_r2 = 1`, picks `blob_credentials`
  from whichever destination is wired, and both agents in `[backup_agent]` and `[backup_agent.2]` are
  fine to start whenever either destination is wired.
- OpenBao's Shamir `sys/rekey/init` and `sys/generate-root/attempt` endpoints return 405 / 404 by
  default; Vault registers them without a flag, OpenBao gates them on
  `disable_unauthed_rekey_endpoints = false` and `disable_unauthed_generate_root_endpoints = false` in
  the listener config (see `internal/http/handler.go` lines 174–192). `service-openbao/config-fdb.hcl`
  now sets both. `bao operator rekey` and `bao operator generate-root` now run.
- The `weftspun-bao root` 1P item is now the single source of truth: `password` CONCEALED holds the
  rotated root token, `unseal_key` CONCEALED holds the rekeyed unseal key, `notesPlain` carries a
  status note only (no secrets). The three stale unseal-key copies (init doc, prior CONCEALED,
  notesPlain) are noted as stale in the item's note. Three orphan root token accessors accumulated
  during rotation attempts and were revoked once `generate-root` came online.

## Also added

- [RFD 2145](https://weftspun.github.io/weftspun-manuals/rfd/2145-certificate-lifetimes/): certificate lifetimes,
  from a risk-based ceiling. Replaces the 10-year CAs and 1-to-2-year leaves RFDs 2134, 2141, 2142, 2144
  landed with. New ceilings: **25 years on the offline Root's `notAfter` with 5-year policy rotation** (X.509
  makes `notAfter` mandatory per RFC 5280 §4.1.2.5, so the field must exist, but rotation is a policy
  commitment rather than a validation gate on an offline key that pays no rent), **3 years on
  intermediates with 1-year rotation**, **90 days on mTLS service leaves with ≤45-day rotation**, and
  **14 days on WebTransport leaves** (Chromium's `serverCertificateHashes` maximum). Citations live as
  `.cff` files under `rfd/2145-certificate-lifetimes/references/` — RFC 5280, Mozilla Root Store Policy
  §7.1's 15-year public-trust cap, CA/B Forum SC-081v3's 200 → 100 → 47 day schedule, NCSC's
  "as short as practical" principle, NIST SP 800-57 Part 1 §5.3.6 cryptoperiod framing, W3C WebTransport.
  RFDs 2134, 2141, 2142, 2144 carry in-place retractions pointing here for the specific numbers replaced.
  S2145 registered.
